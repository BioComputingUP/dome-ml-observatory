API

A read-only REST API over the same corpus Search uses. Good for targeted queries, and for taking the corpus out whole: /api/export pages on a cursor with no result window, so any slice of the data — up to all of it — can be pulled through the API. For a single citable file, bulk download is still the better route.

Open the interactive API explorer Raw OpenAPI spec

The API is documented as an OpenAPI 3.0 contract. The explorer is a Swagger UI rendering of that same document; the raw spec is the machine-readable source, suitable for generating a client.

Recommendations

  • Pulling the whole corpus, or any large slice of it? Use /api/export rather than paging /api/records — it is faster for you, lighter on the service, and it is the only route that reaches past 10,000 records.
  • Ask for limit=1000 per export chunk, or pageSize=100 per search page, to cut down round trips.
  • Keep the X-Next-Cursor value between export calls and stop when it stops coming back — do not guess at the number of chunks.
  • On a 429 or 503, back off exponentially rather than retrying immediately.
  • Cache /api/stats client-side — it only changes when the server-side cache refreshes, at most once a day.
